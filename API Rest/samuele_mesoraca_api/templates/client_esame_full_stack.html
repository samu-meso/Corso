Traccia d'Esame: Backend REST API - Gestione Eventi

Sviluppare un sistema di API REST in Python (Flask) per una piattaforma di prenotazione eventi (concerti, corsi, conferenze). Requisiti dell'applicazione:

  • Modello Dati: id (PK intero), titolo (min 5 caratteri), descrizione (max 250 caratteri), categoria (whitelist), data_evento (formato YYYY-MM-DD), prezzo (decimale $\ge 0.00$), posti_disponibili (intero $\ge 0$), in_evidenza (bool).
  • Endpoint richiesti dal client:
    • GET /api/events: Elenco completo di tutti gli eventi a sistema.
    • GET /api/events/search/{keyword}: Cerca la parola chiave all'interno del titolo o della descrizione dell'evento.
    • GET /api/events/stats: Restituisce un JSON di riepilogo metriche per la dashboard, calcolando la somma totale dei posti ancora liberi e il prezzo medio dei biglietti attualmente a sistema (es. formato atteso: {"posti_totali": 450, "prezzo_medio": 29.99}).
    • POST /api/events: Creazione di un nuovo evento (ID autoincrementale gestito lato server).
    • PATCH /api/events/{id}: Modifica parziale del record (utilizzato dal client per accendere/spegnere lo stato "In Evidenza").
    • DELETE /api/events/{id}: Eliminazione definitiva di un evento.
  • Business Logic e Sicurezza: Un evento non può essere eliminato se è "Sold Out" (ovvero se posti_disponibili == 0), per garantire lo storico dei pagamenti. In questo scenario il server deve rispondere con un codice 403 Forbidden. Qualsiasi dato in ingresso non coerente (stringhe troppo corte, prezzi negativi, categorie non censite) deve restituire un 400 Bad Request.
Consegna Scritta Obbligatoria:
Testate le vostre API con Postman ed il client in dotazione. Sostituire con il proprio nome e cognome i placeholder in basso a destra.
